# Reduce first

Valentin, 2026-10-30:

> THINGS HAVE TO EARN THEIR PLACE

Default to subtraction. Code rules live in pstack (`principle-subtract-before-you-add`, `principle-laziness-protocol`, `principle-experience-first`). This is the same test for what a person sees.

## Before you add anything

1. **Core thing first.** The number, the ad, the decision. First, biggest, and labelled in plain words, so nobody guesses what it is.
2. **The job works.** The action the reader came for works in one step, out of the box, and says what happened, failure included. No empty URL, no disabled placeholder, no "not wired yet". A lean screen with a dead button fails.
3. **List every element, line or field.** Ask each: what breaks if it goes?

| Verdict | When |
|---|---|
| Keep visible | The core thing, the action, the links to go on, a one-word status ("all OK", "failed"), or what the reader needs to decide right now (a score, a count). Small is fine; hidden is not |
| Merge | Two elements say the same thing |
| Hide | Useful later. Closed Details or a link. Never hover only: phones have no hover |
| Delete | Nobody acts on it, it repeats something shown, or you invented it |

4. **Hide, never drop.** Every fact you were given stays reachable. Cutting means moving it out of sight, not losing it.
5. **Then add the smallest form.** A label beats an overlay. A line beats a card. Text boxes stay closed until tapped. No extra buttons, headers, advice or developer notes the task did not ask for.

## Now, was, forecast

Now is big. Was is small. Forecast is labelled and lighter, on its own row. Two numbers for the same thing always say which is older.
