multi-step (more than one deliverable):
1. Find the steps in the order they must ship. Each step is one deliverable a runner can finish and prove in one run.
2. Keep the original ticket as step 1. Rewrite its description so it covers step 1 only: one Problem, one Fix, one Done when line. Rename its title if the old one named the whole job. Say in one line what comes after it.
3. File steps 2 to N in the same board and column with vcc task create --project BOARD --section COLUMN --title ... --description-file FILE --labels "<app label>,<brain tag>". Copy the original's app or cluster labels. Give each exactly one brain tag by brain-rules (light: tiny, one file; medium: normal; hard: hard bug, security, money, many systems). Each has one Done when line.
4. Link each step BlockedBy the one before it: vcc task link STEP_N PREVIOUS_STEP --type BlockedBy. The chain runs one ticket at a time, in order.
5. Add one agent-lane note on the original (vcc activity add KEY --text ...) listing the chain.
A ticket that is only too long, not several deliverables, is rewritten to be shorter instead: one Done when, the same work. Never invent scope. Never drop a requirement: every line of the old ticket lands in a step or is named in the note as left out and why.

too-vague or no-done (one deliverable, written too thinly or with no finish line):
